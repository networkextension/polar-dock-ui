# polar-dock-ui

Static admin + workspace UI for [polar-dock](https://github.com/networkextension/polar-dock).

This repo holds the HTML pages, TypeScript sources, and esbuild-driven
bundling pipeline. The dock binary serves the built artifacts from
`ui/dist/` at deploy time.

## Layout

```
src/        TypeScript entry points + lib/ helpers + api/ + types/
public/     HTML pages + static assets (favicon, styles.css, images)
scripts/    build.mjs — esbuild driver + tsc type-check
server.js   express dev preview (UI_STATIC_DIR=public node server.js)
dist/       build output (gitignored, regenerated by `npm run build`)
```

## Develop

```bash
npm install
npm run build            # tsc + esbuild → ui/dist/ + ui/public/scripts/
npm run build:watch      # rebuild on TS change
npm run preview          # serve dist/ on http://127.0.0.1:8080
```

The dock binary picks up the built files from `ui/dist/` next to its
working directory (typically `<dock-repo>/ui/dist/`). Local deploy
recipe: `rsync -a dist/ <deploy-host>:<dock-repo>/ui/dist/`.

## Pages

Landing + workspace surfaces:
- `dashboard.html` — landing page (site brand + workspace cards)
- `chat.html` — DM + group chat
- `posts.html`, `post.html` — feed + composer
- `markdowns.html`, `markdown.html` — long-form notes
- `rooms.html` — multi-bot group rooms
- `creation.html`, `editor.html` — composition tools
- `teams.html`, `profile.html` — workspace + identity

Admin (gated by `data-admin-nav`):
- `admin.html`, `admin-plugins.html` — users + plugin registry
- `invites.html` — invite-code management
- `llm.html`, `llm-billing.html`, `llm-apps.html` — LLM config + billing + marketplace apps
- `proxy-tokens.html`, `wg-tokens.html` — proxy / WG mesh tokens
- `prompts.html`, `bots.html`, `skills.html` — prompt templates, bots, skill marketplace
- `system.html` — ops dashboard

Plugin-served pages (`expense.html`, `latch.html`, `library.html`,
`hosts.html`, `projects.html`, `video-studio.html`, `iosdist.html`,
etc.) ship from their own plugin repos and are rsynced into
`dist/` at deploy time.
